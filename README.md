# Procyon Archive

База данных кампании *Scum and Villainy* для одного стола. Всё сиюминутное (stress, harm, load,
XP, gambits, текущие броски) остаётся на физическом чарнике. Здесь живёт то, что должно
переживать сессию: экипаж и корабль, персонажи, контакты, фракции, счётчики событий, входящая
почта, артефакты и карта сектора.

Стек: FastAPI + Postgres + React (Vite) + nginx, всё в Docker Compose.

Как выглядит: https://virrius.github.io/procyon-archive-promo/ · установка по шагам для
неайтишника — [INSTALL.md](INSTALL.md).

## Запуск

```bash
docker compose up -d --build
```

| Что | Адрес |
|---|---|
| Веб-интерфейс | http://localhost:5180 |
| API + OpenAPI | http://localhost:8000/api/docs |
| Postgres | localhost:45432 (`procyon` / `procyon` / `procyon`) |

Регистрации нет — учётные записи выдаёт администратор. На пустой базе заводится один админ:
`admin` / `admin`. Пока пароль по умолчанию, интерфейс не пускает дальше окна «Задайте свой
пароль»; потом пароль меняется в Admin space или на экране выбора кампании.

Дальше — **Admin space**:

1. **Язык** (по умолчанию английский) — один на экземпляр: интерфейс и тексты генерации. Язык
   стартовых материалов (фракции, места, бланки, вырезки правил) выбирается при создании кампании,
   по умолчанию — язык интерфейса; заведённое так и остаётся, что бы потом ни переключали.
2. **LLM** — адрес и ключ OpenAI-совместимого сервиса, модели промптов и новостей; кто рисует —
   воркер на этом компьютере или сервис по API.
3. **Кампании** — новая кампания стартует с фракциями и местами книги и картой сектора с их
   отметками; готовую можно загрузить из архива (см. «Перенос кампании»).

Игроки создаются в **GM space**: логин, пароль, имя, роль. Там же сброс пароля, блокировка и
отзыв доступа. Пароль показывается один раз — передай его игроку лично.

Чистый старт (сносит базу):

```bash
docker compose down -v && docker compose up -d --build
```

## Шесть экранов

**Экипаж** — корабль (изображение, класс, системы, документы, AI) с записями, отношения с
организациями, входящая почта и артефакты. Отношения — разворот «Организации» бланка: три колонки
по категориям, только те организации, что стол уже знает, шкала −3…+3 и журнал сделанных дел
(отметка или короткая запись). Уровень отношений ГМ открывает столу поштучно, дела экипаж ведёт сам. Почта — не чат: ГМ пишет письмо от любого отправителя, держит его в черновиках и
публикует, когда нужно; настоящий отправитель виден только ГМу. Игрок отмечает прочитанным,
закрепляет и пишет к письму личную заметку.

**База кампании** — вкладки: Контакты (NPC), Фракции, Счётчики, Работа. Счётчик двигается одним
нажатием, каждое изменение пишется в историю с пометкой «почему». Счётчик можно привязать к любой
записи и сделать скрытым от игроков.

**Персонажи** — карточки с портретами. Игрок видит своего персонажа сверху; ГМ открывает любого.

**Карта Проциона** — сектор с четырьмя системами, орбитами планет и jump-маршрутами (тайные
маршруты видит только ГМ). Клик по системе открывает её карту. На карте можно ставить нумерованные
отметки с обсуждением в боковой панели и рисовать маркером поверх — свои штрихи стираются одной
кнопкой. Фон любого уровня карты заменяется своим изображением.

**Кадры кампании** — то, что стол видел своими глазами: один экран, сверху генерация, снизу
коллекция. Кадры заводит весь стол, не только ГМ. Автор описывает кадр текстом или голосом (пробел
включает микрофон), описание уходит в языковую модель с постановочной инструкцией — тот сам выставляет кадр
и композицию — и возвращает английский промпт, который видно и можно поправить руками перед
рисованием. Нарисованный кадр сначала показывается только автору: тут его можно перерисовать,
сбросить или сохранить в коллекцию с подписью. Готовый файл кладут в трафарет карточки
«загрузить свой кадр» — он попадает в коллекцию сразу. Свой кадр автор подписывает и убирает сам,
любой — ГМ; видимость держит только ГМ и прячет лишнее глазом, скрытый кадр не отдаётся и по
прямой ссылке на файл. Размер страницы галереи выбирается там же и запоминается.

**Правка области** — у сохранённого кадра и у портрета карточки есть кисть: закрашиваешь, что
переписать, и словами говоришь, что там должно оказаться. Просьба уходит в языковую модель вместе с
исходным промптом кадра — правка встраивается в него, иначе модель перепишет весь кадр под одну
фразу. Дальше те же четыре варианта на выбор; выбранный занимает место исходника с его подписью и
видимостью. Сила правки переключается: «заменить» переписывает область начисто, «подправить»
оставляет форму исходника. Незакрашенное не трогается вовсе — оно возвращается в кадр композитом
по маске. Правит воркер, а без него — сервис по API, если это стандартный `images/edits`:
маску держит `gpt-image-2`, а `gpt-image-1.5` и `-mini` перерисовывают весь кадр. Асинхронный
task-API область править не умеет, плашка генерации об этом скажет.

**Доски квестов** — холст ГМа: карточки записей и счётчиков, свободные подписи и кадры, между
ними нити, как на детективной доске. Связи живут только на доске, а записки с карточки уходят в
саму запись (или счётчик) одним блоком под именем доски. Доску можно править и мимо браузера —
снимком и пакетом, см. [docs/boards_api.md](docs/boards_api.md).

**GM space** — учётные записи экипажа, журнал кампании и гардероб. Журнал — одна лента правок:
кто и когда завёл карточку, переписал запись, оставил комментарий, двинул счётчик, отправил
письмо, тронул карту или файл, плюс учётные действия. У правки разворачивается «было → стало»,
а удалённое остаётся в ленте со снимком текста. Лента фильтруется по разделу, автору и поиску
по заголовку; видна только ГМу — журнал знает и о том, что закрыто от стола.

**Admin space** — только администратору, вне кампании: LLM (адрес, ключ, модели картинок и
новостей, кто рисует), промпты картинок и новостей, кампании — выгрузка и загрузка из архива,
пользователи, язык экземпляра. Всё это общее на сервер.

## Перенос кампании

Admin space · Кампании: «выгрузить» собирает zip с картинками, «JSON» — только записи. Архив
собирается на сервере в фоне, ход видно полосой; готовый файл скачивается сам.

«Загрузить из архива» заводит из zip или json новую кампанию: id переписываются, так что архив
можно залить и повторно, и на другой сервер. Остаются участники, чьи учётки есть на этом сервере,
загрузивший становится ГМом, персонажи без игрока — свободными. Всё содержимое — как в архиве,
на его языке.

В `samples/` лежит демо-кампания для загрузки — `demo-silence-over-brekk.zip`, по-английски: две
доски (забастовка на Индри и глобальный движок фракций) и то, что на них опирается, счётчики на
нуле; картинки пережаты в WebP, чтобы архив был легче.

## Как устроена секретность

Видимость задаётся не на страницу, а на отдельную запись: `экипаж` · `выбранным игрокам` ·
`владельцу персонажа` · `только ГМ`.

Фильтрация серверная: скрытые строки не покидают процесс, поля `gm_*` вырезаются до сериализации
(`backend/app/visibility.py`), прямой запрос закрытого объекта по URL или API возвращает 404.
Заголовок `X-View-As: <member_id>` включает для ГМа режим «глазами игрока» — тот же код фильтрации,
что и для самого игрока, и запись заблокирована (409), пока маска не снята.

У каждой сущности мало структурированных полей — всё остальное пишется свободными **записями** с
собственной аудиторией. Так одна страница фракции держит общий текст, слух для одного игрока и
правду для ГМа.

## API для агентов

Всё, что умеет интерфейс, умеет и HTTP API, и контракт лежит в нём самом: Swagger на `/api/docs`,
ReDoc на `/api/redoc`, схема на `/api/openapi.json` (через веб-прокси тоже). Во вводной части схемы —
с чего начать (логин → `/api/meta` → `/api/campaigns` → участники), роли, правило видимости, как
искать id, как устроены долгие операции и что значат коды ошибок. У каждой операции есть `summary`,
описание с побочными эффектами и схемы запроса и ответа; `operationId` — короткое имя функции,
годится как имя инструмента для LLM. Авторизация — `Authorization: Bearer <token>` из `/api/auth/login`.

Правило, ради которого всё это: **что ГМ создаёт без `visibility`, получает `gm`** — ничего не
утекает столу, пока не открыто явно. Ключи `gm_*` в `fields` игрокам не отдаются никогда.

## Своя карта сектора

Положи файл `procyon-sector.png` (или `.jpg` / `.webp`) в папку `assets/` и подними стек с чистой
базой — он станет фоном карты сектора. Уже работающую карту проще заменить прямо в интерфейсе:
на экране карты ГМ нажимает «фон карты» и загружает изображение. Координаты отметок нормализованы
(0..1), поэтому фон меняется без потери разметки.

## Разработка без Docker

```bash
# бэкенд
cd backend
pip install -r requirements.txt
PA_DATABASE_URL=postgresql+psycopg://procyon:procyon@localhost:55432/procyon \
  uvicorn app.main:app --reload

# фронт (проксирует /api на localhost:8000)
cd frontend && npm install && npm run dev   # http://localhost:5173
```

Переменные окружения бэкенда (префикс `PA_`): `DATABASE_URL`, `JWT_SECRET` (без него секрет
заводится при первом старте в `UPLOAD_DIR/.jwt_secret`), `JWT_TTL_HOURS`, `UPLOAD_DIR`, `WORKER_TOKEN`. Язык и подключение LLM задаются в Admin space, не окружением.

Поля сущностей описаны в `backend/app/schema_defs.py` — фронт рендерит формы и карточки из этого
описания, так что новое поле добавляется одной строкой. Ключи с префиксом `gm_` автоматически
становятся GM-only.

## Схема данных

```
Campaign ─┬─ CampaignMember ── User
          ├─ Entity (kind: character | npc | faction | crew | ship | location | mission | item)
          │    ├─ ContentBlock   (записи, видимость на запись)
          │    ├─ Clock ── ClockEvent   (счётчики и история изменений)
          │    ├─ EntityLink   (связи, задел на граф)
          │    └─ Attachment
          ├─ Message ── MessageState    (прочитано / закреплено / личная заметка)
          ├─ Event                      (журнал правок: кто, когда, было → стало)
          ├─ MapNode ─┬─ MapMarker ── Note   (отметки и обсуждения)
          │           ├─ MapEdge            (маршруты)
          │           └─ MapStroke          (рисование маркером)
          └─ AuditLog
```

## Чего здесь нет и не будет

Броски кубов, расчёт position/effect, полный цифровой чарник, combat tracker, initiative,
голос и видео, 3D-стол, автоматизация правил. Сервис не заменяет физический стол.

Новая кампания получает только канон сектора из книги — фракции и места без картинок, карту
с отметками; всё это правится или удаляется.
